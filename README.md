# crm-account-reconciliation-lab

A one-week slice: reconcile **synthetic** Salesforce-shaped
Account exports from two orgs with deterministic blocking, a Splink baseline,
and a typed AI judge, scored against a bar that was frozen and pushed before the
published run.

**Results:** [`results/index.md`](results/index.md) (written by the published run; absent until then).

> **Provenance (written 2026-10-02, ET).** I designed and built this repository on 2026-10-02 as a personal portfolio project. All data here is synthetic, generated by `src/recon_lab/generate.py` from fixed seeds, and contains no real customer, company, or personal data. Company names come from fictional word lists. All websites and emails use the reserved `.example` domain (RFC 2606), and phone numbers use the fictional 555-0100–0199 range. The workflow idea draws only on publicly available descriptions of multi-CRM consolidation. No confidential, non-public, recruiter-provided, interview, or take-home material from any company was used. The measurement modules in `src/recon_lab/vendor/crashlab/` are copied from Agent-Crash-Lab (MIT) at commit 8a3f865; see that folder's LICENSE and VENDORED.md. This is a demonstration, not a product, and it is not affiliated with or endorsed by Salesforce, Snowflake, dbt Labs, or any other vendor.

## What is in the slice

- `src/recon_lab/generate.py`: two orgs x 1,000 Accounts, 250 shared companies, 40 intra-org duplicates per org, 75 hard-negative "twins" (same coined first word, different company). Salesforce export columns, 18-character case-safe Ids, UTC DateTimes. Ground truth in `data/ground_truth/<seed>/entity_map.csv`. Dev seed 101; test seed 202 adds one corruption family never seen in dev (`rebrand_domain`, about 15% of shared copies).
- `src/recon_lab/blocking.py`: union of four rules (normalised domain; first 4 name characters + ZIP5; full 10-digit phone; Soundex of first name token + state).
- `src/recon_lab/baseline.py`: Splink 4.0.17 (DuckDB), trained on the dev seed only and frozen in `config/frozen/splink_model.json`.
- `src/recon_lab/judge.py`: the typed AI judge. Prompt published at `prompts/account_match.v1.md`; its sha256 goes into every run log. Answers are parsed by the vendored `TypedAnswerParser`; anything malformed becomes a typed missing answer. Returned model versions are logged by the vendored `model_version_log` (`mark_invalid` policy). Spend is estimated from token usage.
- `src/recon_lab/decide.py`: Splink auto-merges at or above its dev-frozen match weight; every other blocked candidate goes to the AI judge (2 repeats, mean of non-missing); the AI's dev-frozen cutoffs split those into auto-merge, no-match, or review. Decisions go through the vendored `DecisionLedger` (shadow run first, then score with the same threshold fingerprint).
- `src/recon_lab/evaluate.py`: pairwise precision/recall with Wilson 95% bounds, calibration (vendored), and the frozen bar.
- `results/`: `index.md`, `metrics.json`, `review_queue.csv`, `calibration.md`.

## Pre-registration

1. `config/protocol_rules.json` (committed before any AI call): bar, cutoff-selection rules, caps, prompt and model settings.
2. Dev run on seed 101 picks the cutoffs by those rules (`runs/dev_selection.json`).
3. `config/frozen/protocol.json` records the cutoffs plus sha256 of the rules, prompt, Splink model and test data, and is committed and pushed **before** the published run. The published run refuses to start if that file is uncommitted, not on `origin/main`, or if any hashed input changed.
4. One published run on seed 202. No re-run on the same seed.

Verdict templates, written before the run:

- PASS: "On a synthetic, seeded two-org Account dataset, the cascade met every pre-registered criterion: blocking recall [BR]; Splink-only P/R [P_b]/[R_b]; cascade auto-merge precision [P] (Wilson 95% lower bound [LB]) and recall [R]; review queue [Q]; missing/malformed [MISS]; model [SNAPSHOT]; spend [$]."
- Negative (criterion 5 fails): "Deterministic baseline sufficient on this synthetic data; the AI judge added no lift at the frozen cutoffs." Followed by the same numbers.
- Invalid (criterion 1, 2, 7 or 9 fails): no accuracy claim; the cause is reported.

Limits stated up front: the ground truth is circular (this repo wrote the corruption model); the unseen family in the test seed is the partial mitigation. Nothing here measures real CRM data, production readiness, or any vendor.

## Run it

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"
python -m pytest -q                  # offline unit tests
python scripts/boundary_check.py     # private-name and domain check over tracked files
python -m recon_lab.cli generate     # writes data/ for seeds 101 and 202
python -m recon_lab.cli train-baseline
export OPENAI_API_KEY=...            # read from the environment only; never committed or logged
python -m recon_lab.cli dev          # dev run + cutoff selection (cap $10)
python -m recon_lab.cli freeze       # writes config/frozen/protocol.json -> commit and push it
python -m recon_lab.cli publish      # one-shot published run (cap $10)
```

Spend caps: $10 development, $10 published run, $20 hard ceiling; the client stops issuing calls at a cumulative $15 estimate.

## CI

The GitHub Actions workflow (boundary check, offline unit tests, gitleaks) is staged at `ci/github-actions-ci.yml`. It is not active yet: pushing to `.github/workflows/` needs a token with the `workflow` scope, which the build token lacked. Move it to `.github/workflows/ci.yml` to switch it on. `scripts/ci_local.sh` runs the same three checks locally. The boundary check fails on private project names and on any email or URL whose domain is not `.example` or `.invalid`; it scans every tracked text file.
